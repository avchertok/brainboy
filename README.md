# BrainBoy — рейтинг команд

Пайплайн для анализа экспорта чата WhatsApp: извлечение результатов игр
BrainBoy с фотографий таблиц через vision-модель и статическая веб-страница
с рейтингом команд.

Про игру: 8 раундов (8-й — «капитанский конкурс»), игры проходят по
воскресеньям. В таблице результатов — очки по 8 раундам, итоговая сумма
и место команды.

## Структура проекта

```
pipeline/
  parse_whatsapp.py    # парсер экспорта WhatsApp → data/raw/messages.json
  extract_images.py    # отбор картинок-кандидатов → data/media/, data/raw/candidates.json
  vision_extract.py    # извлечение таблиц с фото через vision API → data/drafts/
  merge_drafts.py      # консолидация черновиков, дедупликация → data/results.json
  build_data.py        # сборка web/data.json из курируемого data/results.json
data/
  raw/                 # экспорт чата и промежуточные JSON (не коммитится)
  media/               # отобранные фото результатов (не коммитится)
  drafts/              # черновики авто-извлечения (не коммитятся)
  results.json         # курируемые вручную результаты игр (коммитится)
web/
  index.html           # статическая страница рейтинга
  data.json            # сгенерированные данные для страницы (коммитится)
```

## Важно: экспорт чата обязательно С МЕДИА

Пайплайн работает по фотографиям таблиц результатов, поэтому экспорт нужно
делать с вложениями. В WhatsApp:

- **iPhone:** откройте чат → имя чата вверху → прокрутите вниз →
  «Экспорт чата» → выберите **«Прикрепить файлы»** (не «Без файлов»).
- **Android:** чат → ⋮ (меню) → Ещё → Экспорт чата → **«Прикрепить файлы»**
  («Include media»).

Получится zip с `_chat.txt` и файлами вложений. Обратите внимание: WhatsApp
может ограничивать количество вложений в одном экспорте (обычно последние
~10 000 сообщений с медиа) — для длинной истории может понадобиться экспорт
по частям.

Если экспорт был сделан «без файлов», `extract_images.py` не найдёт ни одной
картинки и напечатает агрегированный отчёт: сколько фото приходится на какие
воскресенья — пригодится для сверки после повторного экспорта.

## Как пользоваться

1. **Парсинг чата:**

   ```bash
   python3 pipeline/parse_whatsapp.py путь/к/export.zip
   ```

   Поддерживаются оба формата экспорта (iOS и Android). Результат —
   `data/raw/messages.json`.

2. **Отбор картинок-кандидатов** (по ключевым словам в тексте рядом с фото,
   либо все картинки с флагом `--all`):

   ```bash
   python3 pipeline/extract_images.py
   ```

   Кандидаты копируются в `data/media/`, список — `data/raw/candidates.json`.

3. **Извлечение таблиц с фото через vision-модель.** Сначала настройте
   окружение:

   ```bash
   cp .env.example .env   # и впишите OPENAI_API_KEY
   pip install -r requirements.txt
   ```

   Затем:

   ```bash
   python3 pipeline/vision_extract.py
   ```

   Черновики складываются в `data/drafts/<имя-картинки>.json`. Уже
   обработанные картинки пропускаются (перезапись — `--force`).

   Каждый черновик содержит извлечённую таблицу (8 раундов, итог, место)
   и блок `candidate_dates` — варианты даты игры: EXIF фото, дата сообщения
   в чате и ближайшее прошедшее воскресенье (игры проходят по воскресеньям).

4. **Консолидация черновиков и валидация дублей.** Одну таблицу могли
   скидывать в чат несколько раз разные участники — `merge_drafts.py`
   группирует черновики по вычисленной дате игры, находит дубли
   (одна дата + пересекающийся состав команд) и сверяет очки:

   ```bash
   python3 pipeline/merge_drafts.py          # dry-run: только отчёт
   ```

   Отчёт показывает:
   - какие игры будут добавлены и из каких черновиков;
   - **конфликты** — расхождения в очках между дублями одной игры
     (их нужно проверить вручную по фото);
   - похожие названия команд, которые стоит замерджить через
     `team_aliases` в `data/results.json`.

   Когда отчёт устраивает:

   ```bash
   python3 pipeline/merge_drafts.py --apply  # дописать новые игры в results.json
   ```

   Игры с датами, уже существующими в `results.json`, никогда не
   перезаписываются — курируемые данные в безопасности.

5. **Ручная курация `data/results.json`.** Формат:

   ```json
   {
     "team_aliases": {"брейн бой": "BrainBoy", "Brain Boy": "BrainBoy"},
     "games": [
       {
         "date": "2026-02-15",
         "title": "Чемпионат ОАЭ",
         "venue": "Бар «Улей»",
         "teams": [
           {
             "name": "BrainBoy",
             "place": 1,
             "rounds": [8, 7, 6, 9, 5, 7, 8, 10],
             "total": 60
           },
           {
             "name": "Гости из Дубая",
             "place": 2,
             "guest": true,
             "city": "Дубай",
             "rounds": [7, 7, 5, 8, 5, 6, 8, 9],
             "total": 55
           }
         ]
       }
     ]
   }
   ```

   - `rounds` — очки по 8 раундам по порядку (8-й — капитанский конкурс);
     `null` для нечитаемых ячеек.
   - `title` и `venue` опциональны; `title` (например, «Чемпионат ОАЭ»)
     показывается бейджем у карточки игры.
   - Сезон по умолчанию вычисляется из `date` (сезон = календарный год).
     Если организатор засчитал игру в другой сезон, добавьте игре
     необязательное поле `"season"` (например, `"season": 2025` у игры
     с датой `2026-01-04`) — она попадёт в сезонные рейтинги указанного
     сезона, а на странице получит пометку о переопределении.
   - **Гостевые команды.** Команда с `"guest": true` (+ необязательный
     `"city"` для плашки, например `"Дубай"`) играет вне зачёта: она видна
     в таблице игры (полупрозрачной, с плашкой города), но не попадает в
     рейтинги, историю и статистику. `place` храните общим, как на фото;
     `build_data.py` сам пересчитает зачётные места не-гостей
     (`effective_place` — место среди не-гостей), которые идут в
     олимпийскую систему, победы и подиумы.
   - `team_aliases` приводит вариации названий к каноническому имени.

6. **Сборка данных для страницы:**

   ```bash
   python3 pipeline/build_data.py
   ```

   Генерирует `web/data.json`: стендинги за всё время и по сезонам в двух
   системах рейтинга («по сумме очков» и «олимпийская»: 1 место = 3 очка,
   2 = 2, 3 = 1), историю накопительного рейтинга для графика и статистику
   по раундам (средние очки, лидер капитанского конкурса).

7. **Локальный просмотр:**

   ```bash
   cd web && python3 -m http.server 8000
   ```

   Откройте http://localhost:8000

8. **Деплой на Vercel.** Проект настроен как чистая статика из папки `web/`
   (см. `vercel.json`). Достаточно подключить репозиторий к Vercel или
   выполнить `vercel deploy`.

## Приватность

Экспорт чата содержит личную переписку и номера телефонов, поэтому
`data/raw/`, `data/media/`, `data/drafts/`, `*.zip` и `_chat.txt` игнорируются
git и никогда не коммитятся. Коммитятся только курируемый `data/results.json`
и сгенерированный `web/data.json` — следите, чтобы туда не попадало ничего
лишнего. Ключ API хранится в `.env` (тоже игнорируется); шаблон — `.env.example`.
